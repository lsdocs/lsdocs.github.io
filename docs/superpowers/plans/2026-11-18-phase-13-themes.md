# Phase 13 Flagship Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** render-html gets a theme system and a built-in flagship theme, `default` (zensical-ui's look, our own code), with search, dark mode, code copy, content tabs and toc highlighting.

**Architecture:** render-html splits into a body writer emitting the `lsd-` markup contract, a theme loader (directory or built-in, `theme.toml` settings, overrides), and asset output (hashed, written at `render/transform/all` with the search index). The `default` and `plain` themes live in `plugins/render-html/themes/`, embedded at build time. Theme JavaScript is TypeScript compiled by `tsc` to ES modules, checked in.

**Tech Stack:** Rust (minijinja), plain CSS, TypeScript 6 via `tsc` (no bundler), `@preact/signals-core` (vendored ESM), Node's `node:test` for the theme's pure logic.

**Spec:** `docs/superpowers/specs/2026-11-18-phase-13-themes-design.md`

## Global Constraints

- Prefix `lsd-` for markup classes, custom properties (`--lsd-...`) and elements (`<lsd-search>`).
- Built-in themes: `default` (the flagship, the default) and `plain` (today's template; its page toc a drop-down menu).
- No CSS framework, no Sass, no bundler; TypeScript compiled by `tsc` only, output checked in, regenerated by `nur gen theme`; building or using lsdocs needs no Node.
- No third-party requests by default (system fonts, no CDN, no analytics); consent and banners are state in `localStorage`, no cookies.
- Theme settings live in render-html's settings file (`theme`, `[theme]`, `overrides`); `site.theme` is removed from `lsdocs.toml`.
- `nur ci` passes per task; branch `feat/phase-13-themes`, ff-merged into `main`, pushed.

## Review Focus

- A page with no headings, no nav or no toc renders without empty widgets or template errors: test in Task 3 (`renders_a_bare_page`).
- A theme override that replaces one block keeps the rest of the theme: test in Task 3 (`overrides_replace_one_block`).
- An unknown or wrong-kind key under `[theme]` is an error naming the file: test in Task 3 (`theme_settings_are_validated`).
- Asset references survive a site served from a subdirectory (`base_url = "/docs/"`, pages in subfolders): test in Task 3 (`asset_urls_are_relative`).
- Search with no matches, and with HTML or regex characters in the query, shows "no results" and never injects markup: test in Task 6 (`search_escapes_and_handles_no_matches`).
